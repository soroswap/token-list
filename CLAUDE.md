# soroswap/token-list

## Entry summary

Curated list of Stellar / Soroban assets that Soroswap trusts for validating swap paths on its AMM (`README.md:3`).
Source of truth is `assets/<CONTRACT>.json`, one file per token (`README.md:40`); `tokenList.json` is the generated aggregate, regenerated by CI after merge and never hand-edited (`README.md:55`).
The asset schema lives once, in the `assetSchema` object exported by `scripts/lib/assetSchema.js`: `name` and `org` required, plus either `contract` or `code`+`issuer`; `additionalProperties: false`.
List metadata: `name`, `provider`, `description`, `version`, `feedback`, `network`, `assets` (`tokenList.json:2-8`), currently version `1.5.1` on `mainnet` with 47 assets.
Distribution is the repo file plus a POST to the Soroswap indexer after every merge that touches `assets/**` (`.github/workflows/update-token-list.yml:45-53`).

## Commands

From `package.json:12-19`. Run them from the repo root; the scripts resolve `./tokenList.json` against the CWD.

| Command | Does |
|---|---|
| `yarn test` | Unit tests, no network. |
| `yarn verify` | Schema plus on-chain validation of `assets/`. The PR gate. |
| `yarn merge` | Regenerates `tokenList.json` and bumps `version`. |
| `yarn set-trustlines $SECRET` | Adds trustlines for every classic asset in the list. |
| `yarn restore-footprints` | Restores Soroban footprints for listed contracts. Needs `PRIVATE_KEY`, `RPC_URL`, `HORIZON_URL`, `SOROSWAP_API_KEY`. |
| `yarn restore-footprints:env` | Same, sourcing `.env` first (`scripts/restore-footprints.sh`). |

Requires Node 22.12 or newer (`package.json:9-11`): `@stellar/stellar-sdk` 17 needs `require(esm)`.

Adding a token: fork, add `assets/<CONTRACT_ADDRESS>.json`, run `yarn && yarn verify`, open a PR that changes nothing else and fill in the template (`README.md:29-56`).

## Conventions

- Never commit secrets. `.env.local.example` lists variable names only; workflows read `PRIVATE_KEY`, `RPC_URL`, `SOROSWAP_API_KEY`, `TRUSTLINES_PRIVATE_KEY`, `INDEXER_URL`, `INDEXER_GITHUB_API_KEY` from GitHub secrets. Never log a secret key.
- The asset schema exists once, in `scripts/lib/assetSchema.js`. The PR gate and the merge both import it. Do not copy it.
- `scripts/*.js` are composition roots: env, file I/O, `process.exit`. Behavior goes in `scripts/lib/` with a test in `tests/`, written before the code.
- Verify before trusting: if a claim in these docs contradicts the code, the code wins. Fix the doc in the same commit.

## Module Documentation Convention (MANDATORY)

Every module has a living doc at `docs/modules/<module>.md` (flat file, one per module). `docs/modules/README.md` is the index that routes a module's source path to its doc. These are the fast on-ramp for anyone, human or agent, touching a module.

**Progressive disclosure, do NOT load all docs at once.** When you are about to touch a module, open `docs/modules/README.md`, find the ONE doc matching the code you are changing, and read only that. Never pull the whole `docs/modules/` folder into context.

**The workflow rule:**
1. **Before modifying a module, read its `docs/modules/<module>.md` first.** It holds the file map, key methods with `file:line`, dependencies, and gotchas.
2. **After modifying a module, update its doc in the same change.** New or removed behavior, changed schema, new gotchas, dependency changes: all go into the doc before the work is done. Bump the "Last verified" date.
3. Doc claims must be verified against source and cite `file:line`. Never document something you have not confirmed exists.
4. **Adding a new module?** Create its `docs/modules/<module>.md` and add a row to `docs/modules/README.md` in the same change.

Docs follow a shared template: Purpose, Structure, Endpoints/Public surface, Key methods (`file:line`), Dependencies, Gotchas & invariants, Testing.
